&#x20; Blocages Prioritaires



&#x20; 1. Le contrat API Android ne correspond pas au backend réel:

&#x20;     - Android appelle GET day-score/{date} dans mobile-android/app/src/main/java/com/smartlife/mobile/core/network/

&#x20;       ApiService.kt:33, mais Spring expose GET /api/score/today.



&#x20;     - Android appelle GET timeline/items, mais Spring expose GET /api/timeline.

&#x20;     - Android appelle PATCH tasks/{id}/complete, mais Spring expose PATCH /api/tasks/{id}/status?status=DONE.



&#x20; 2. L’authentification est incompatible:

&#x20;     - Android attend accessToken et role dans mobile-android/app/src/main/java/com/smartlife/mobile/feature/auth/data/

&#x20;       model/AuthModels.kt:19.



&#x20;     - Spring renvoie token, sans rôle, dans backend/src/main/java/com/smartlife/dto/AuthResponse.java:7.

&#x20;     - Le refresh Spring renvoie uniquement accessToken, pas un objet AuthResponse complet.



&#x20; 3. Le flux OTP Android est incomplet:

&#x20;     - Spring attend {userId, code}.

&#x20;     - Android envoie {email, otp}.

&#x20;     - La route OTP est déclarée dans mobile-android/app/src/main/java/com/smartlife/mobile/core/navigation/

&#x20;       Screen.kt:7, mais aucun écran OTP n’est raccordé à la navigation.



&#x20;     - L’inscription Spring peut renvoyer {step: "OTP\_REQUIRED", userId}, pas systématiquement AuthResponse.



&#x20; 4. Le stockage des tokens n’est pas suffisamment sécurisé:

&#x20;     - mobile-android/app/src/main/java/com/smartlife/mobile/core/datastore/TokenDataStore.kt:15 stocke access token et

&#x20;       refresh token en clair.



&#x20;     - mobile-android/app/src/main/AndroidManifest.xml:12 autorise les sauvegardes.

&#x20;     - Il faut chiffrer le refresh token et exclure les tokens des backups.



&#x20; 5. Le refresh JWT automatique n’est pas implémenté:

&#x20;     - mobile-android/app/src/main/java/com/smartlife/mobile/core/network/AuthInterceptor.kt:14 ajoute le bearer token,

&#x20;       mais ne traite pas les réponses 401.
